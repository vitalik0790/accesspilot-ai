# MVP threat model

## Scope and trust boundaries

Assets include page content, questions, API credentials, API budget, and the user's ability to make informed decisions. Webpage text, DOM attributes, and AI output are untrusted. The popup, packaged service worker, extractor, and local analyzer form the extension boundary; OpenAI and browser/OS speech services are external processing boundaries. The source and dependency supply chain must also be trusted to build an extension.

The current MVP reads and explains content. It does not click page controls, fill forms, navigate on the user's behalf, make purchases, or execute model-selected tools. A compromised browser, OS, or installed extension package is outside the protection this MVP can provide.

| Threat | Current mitigation | Remaining limitation |
| --- | --- | --- |
| Prompt injection in webpage text or labels | Fixed instructions identify page content as untrusted; page data is serialized separately inside the input; no tools or action execution are enabled. | Prompting is not isolation. A model can still follow malicious content or give misleading instructions. JSON does not neutralize prompt injection. |
| Malicious webpage content or AI output | Only selected text/cues are extracted in Chrome's isolated script context. No raw HTML is sent. React renders answers as text; no raw-HTML rendering or model-supplied executable links. CSP restricts packaged scripts and network destination. | Malicious content can influence answers. Huge or pathological DOMs may cause slow extraction; output limits do not bound total traversal work. The analyzer is heuristic. |
| Sensitive information in visible content | No form values, editable text, or detected hidden text is extracted. AI actions require explicit popup consent and have bounded payloads. Local scanning stays local. | Titles, visible text, alt/ARIA labels, or values mirrored into normal text can contain secrets. There is no general redaction engine. Visibility filtering is incomplete. |
| API key exposure | Key configuration and builds are ignored by Git; no credential logging; HTTPS API requests. | The development key is recoverable from the built worker. A public keyed bundle is unsafe. A secure backend is planned, not implemented. |
| Unauthorized extension messages | Listener checks the sender extension ID and exact popup URL. Request type, question length, and AI consent flag are validated. No external messaging listener is registered. | A compromised trusted popup/package can send valid messages. Consent is a boolean for the popup session, not tied to a particular document. Sender checks do not mitigate compromised dependencies. |
| Excessive browser permissions | Only `activeTab`, `scripting`, and the OpenAI host are requested. Extraction is user initiated. No all-sites content-script registration, storage, or microphone permission. | Invoking the extension grants temporary access to the active page, which may be sensitive. The API host grant is broader than a single URL path. Future features require a new review. |
| AI hallucinations or missing context | Grounded-answer instructions, short output, truncation notice, plain-text presentation, and a warning to verify important details. Screen-reader use remains supported. | Summaries may omit or invent details, especially with truncated, virtualized, or poorly structured pages. No accuracy guarantee or source-to-answer verification exists. |
| Unsafe future agent actions | No action tools exist today. | If actions are added, require explicit human confirmation for sensitive operations, clear previews, scoped authorization, cancellation, and verification. Model or webpage instructions must never constitute user approval. |
| Unexpected speech or interference with assistive technology | Automatic speech defaults off; manual start/stop; current opt-in checked when replies arrive; speech cancelled when disabled or popup closes. | Browser/OS speech may process text remotely. Screen-reader speech can overlap; actual compatibility needs user testing. |
| Excessive cost or provider failure | Popup prevents concurrent duplicate submissions, limits questions and extracted output, requests a 600-token response cap, and uses a 25-second fetch timeout. | No account-wide rate limits or budget enforcement. Repeated requests still incur costs; closing the popup need not cancel provider work. |
| Dependency or repository compromise | Lockfile, restricted build-script allowance, ignored local secrets/builds, and behavior tests. | No automated dependency security monitoring or provenance verification is configured. Tests are not a supply-chain audit. |

## Before wider distribution

Resolve project-owned credential handling before shipping keyed packages. Test with blind and visually impaired users using non-sensitive pages, review actual network payloads, and test speech/keyboard behavior in Chrome with assistive technology. Review changes to permissions, message handlers, extraction, model input, or future action capabilities against this table. Report vulnerabilities privately to the maintainer through an available private contact channel; do not put credentials or sensitive page content in public issues.
